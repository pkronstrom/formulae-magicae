# Product brief

**Minimum inputs.** A goal, sketch, existing project or physical object, plus known hard constraints. Start with a quick design pass using placeholders for geometry when needed. Mark assumed dimensions. Ask what someone does with the gadget and how they will tell it works.

**Do.** Sketch one or more directions early. Compare consequential experience, size, power and delivery tradeoffs. Record musts, preferences and unknowns, including acceptable work on arrival. Separate design-file, kit and assembled delivery goals. If the user has a case or named supplier, capture it now and use the delivery/enclosure guide. A narrower scope can defer detailed firmware behavior while preserving host interaction and interface requirements.

**Make a quick product-design pass before choosing parts.** Walk through the main use scenario from the user's point of view. Sketch how the gadget sits or is held, what it displays, and where fingers reach. Compare the number and type of controls, what needs to fit on the display, and what the gadget should do when connected, idle, or unplugged. For a direct-plug gadget, include the host edge and occupied adjacent ports. Decide what needs to work away from USB before considering a battery. Use rough envelopes for screens, buttons and connectors. Show tentative placement, proposed openings and relevant clearances on the sketch. Keep dimensions and implementation choices provisional until checked. Record the agreed interaction, placement anchors and power behavior as inputs to architecture. Set aside detailed firmware design for its own phase.

**Choose a visual.** Use Codex ImageGen when available and a realistic concept would help the user judge appearance or interaction. Show the gadget in context, such as plugged into a laptop or held in a hand. Use a supplied sketch, a simple drawing or a rough CAD mockup when that makes the decision clearer. Label generated imagery as a concept and record any assumptions about scale, placement and materials. Use measured or dimensioned views when the decision depends on fit.

**Capture `brief`.** Output roles `brief` (versioned product brief with requirements and success criteria) and `visual` (concept or annotated views). Provide the `direction` check, then obtain the planning decision on this scope and product direction. Reopen it when the intended experience, physical goal or delivery commitment changes.
