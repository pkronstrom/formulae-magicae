# Assign MCU pins against the floorplan

Start at contracts with the exact orderable part and package, its pinout and alternate-function tables, the required modes of operation, and a rough arrangement of the fixed endpoints. Revisit the map at arrangement when actual footprints, board faces and keepouts are available.

1. **Work in board coordinates.** On the existing placement visual, label the viewing side, MCU pin 1, rotation, and the destination pads for each signal group. For a bottom-mounted MCU, read the transformed pad positions from the PCB editor. A datasheet top view, a connector mating view and a top-down board view can each have a different left and right.
2. **Allocate the least flexible signals first.** Reserve supplies, exposed pad, reset, boot, programming/debug and any dedicated interface pads the design uses. For each remaining function, list the legal pads on this package. Filter by voltage domain, direction and drive, reset state and external pulls, and any required analog, interrupt or wake behavior in the intended power mode. Assign peripheral groups together so their instance, alternate functions and shared resources work simultaneously. A pin with one legal choice takes precedence over a button with ten.
3. **Compare legal orientations before allocating ordinary GPIO.** Hold the product's fixed endpoints in place. For each plausible rotation, sketch a short breakout for the hardest interface and its return, plus room for the supply capacitors. Discard rotations that obstruct these paths. On each remaining candidate, assign interchangeable GPIOs to pads facing their destination corridor. Match pad order along that edge to the order the traces enter the corridor. Three adjacent button pins can still cross if their order is reversed. Account for required board-face transitions and any obstacles between the pads and their destinations.
4. **Trial the best candidate against the baseline.** Keep other placement and router settings fixed for a pin-map comparison. Inspect actual critical paths and count signal layer changes on the reassigned nets. Check full-board connectivity, DRC and schematic parity. Break ties in favor of the simpler breakout and an existing verified pin map. If several things changed together, attribute the measured result to the combined trial.
5. **Publish the selected map once.** In the project's pin contract, record signal and destination pad, MCU port/pad number, peripheral/alternate function or GPIO mode, boot and sleep requirements, and the exact datasheet reference. Mark fixed and swappable entries. Put the chosen orientation and group escapes on the arrangement visual. Carry a swap through the schematic and PCB, firmware board definitions or handoff, and any affected test or programming instructions. Recheck the changed interfaces before accepting the revision.

For example, on a USB key, reserve USB and debug first. A clock interrupt that must wake the MCU gets a pad verified for that wake mode. Assign ordinary buttons last, in their physical order, after reserving the USB corridor. A nearby pin with restricted output drive needs an electrical check before it can serve as a peripheral reset. On STM32U545 boards, the package drawings, pin-definition footnotes and alternate-function tables describe different parts of this decision.
