# PCB routing capability

Start with the netlist, accepted placement, supplier stackup and constraints, and keepouts from enclosure, debug, electrical and assembly work. Use native PCB tools as available. Route consequential electrical classes first according to the applicable reference and known stackup, then remaining nets. Record any accepted layout exceptions and why they affect only the named checks or claim.

## Routing rules of thumb

- **Set constraints before drawing traces.** Use the actual fab stackup and the applicable interface and device requirements to set widths, gaps and via rules. Leave margin above fabrication minimums where space allows. Apply controlled impedance and length matching where the interface calls for them. [Example fab capability table](https://jlcpcb.com/capabilities/pcb-capabilities/), [example device-specific USB guidance](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/pcb-layout-design.html#usb)
- **Route the return path with the signal in mind.** Keep fast signals over a continuous reference plane. Avoid crossing plane splits or cutouts. When changing layers, provide the local return path required by the design. A ground pour that looks continuous at a glance can still have slots and bottlenecks after filling. [Analog Devices on return current](https://www.analog.com/en/resources/analog-dialogue/articles/2022/09/02/02/40/what-are-the-basic-guidelines-for-layout-design-of-mixed-signal-pcbs.html), [Espressif USB layer transitions](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/pcb-layout-design.html#usb)
- **Keep power loops compact and noisy copper away from sensitive signals.** Review the entire loop through the component, bypass capacitor and return. For switching supplies, use the regulator's recommended hot-loop and switch-node geometry. Check power traces, neck-downs and vias against the relevant current, voltage-drop and thermal budget. [TI high-current paths and bypass loops](https://www.ti.com/document-viewer/lit/html/SSZTAL0/GUID-CF03725F-911C-4A96-9391-0E639F290409), [TI buck layout](https://www.ti.com/document-viewer/lit/html/SSZT090/GUID-D62264EC-5FF1-497C-9311-E3E043EE6B4F)
- **Finish on the filled board.** Refill zones before checking, inspect critical copper paths and keepouts on the layer views, and run DRC with the intended project rules and schematic comparison where supported. Resolve unintended unconnected nets and explain any exclusions. [KiCad design-rule checking](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#_design_rules_checking)

Inspect connectivity, board/schematic agreement where the tool can check it, DRC, return paths, power paths, noise-sensitive placement, test/programming access, antenna restrictions and the actual production rules that apply. ERC/DRC do not establish signal integrity, device behavior, or tolerances not modeled by those checks. If a new keepout or placement change affects a reviewed arrangement, send the proposal back through that phase before accepting routing.

## Reducing avoidable vias

Treat a requested via count as a project target. Record whether it applies to signal vias or the whole board, and whether it is a preference or a fabrication limit. Use this loop on manual or autorouted boards.

1. **Count the baseline on filled copper.** Count physical vias once each and group them by net. Inspect their locations to distinguish signal layer changes, power and ground connections, stitching or return vias, and thermal vias. A ground via can serve several purposes. Mark a cluster on the layer view and follow its traces to find what forced the changes.
2. **Fix the largest avoidable cluster first.** Several signals hopping over the same row of test pads suggest moving the row or rotating a part. A single signal hopping out and immediately back suggests rerouting the local crossing. Try a direct path on one layer and reserve the tight corridor for the least flexible net. In a batch router, trial a higher via cost or preferred signal layer when supported. Check the result for long detours.
3. **Review plane connections separately.** A same-side ground pour or short local supply area can serve adjacent pads. After refill, trace the connection to the main plane and check for isolated islands and narrow necks. Share a power via only if its current capacity and the resulting bypass loop meet the device guidance. Preserve needed reference stitching, ESD returns, thermal vias and parallel current paths. [TI bypass-loop guidance](https://www.ti.com/document-viewer/lit/html/SSZTAL0/GUID-CF03725F-911C-4A96-9391-0E639F290409), [Analog Devices grounding and decoupling guidance](https://www.analog.com/en/resources/analog-dialogue/articles/2022/09/02/02/40/what-are-the-basic-guidelines-for-layout-design-of-mixed-signal-pcbs.html)
4. **Keep a measured improvement.** On a copy, change one suspected cause, preserve a baseline, and rerun with comparable rules and router settings. Record the change, open connections, DRC and schematic parity findings, via counts by purpose, and any detour on a critical path. Inspect differential pairs between corresponding endpoints and across their reference copper. Aggregate net lengths can include branches. Choose a candidate that meets the electrical, mechanical and fab constraints, then favor fewer avoidable vias. Stop when the preference is met or the remaining vias have a documented purpose. If a hard cap remains unmet, reopen the relevant placement, pinout or stackup decision.

## Optional autorouting

Use the [hardware Compose starter](hardware-containers.md#kicad-and-routing) for pinned KiCad, native KiCadRoutingTools routing or Freerouting DSN/SES exchange.

Let the agent plan the net order, corridors, layers and permitted vias. Use a PCB routing tool to create the geometry. Work on a separate copy of the accepted placement and carry over its project rules. Check tool access and a small round trip before committing to a batch workflow, especially if the tool runs in a container or another agent's sandbox. [PCBRouteAgent planner and routing-engine experiment](https://arxiv.org/abs/2611.08175)

1. **Check routability before the bulk pass.** Put support parts next to the pins they serve. On a dense board, try escaping the tight package and routing one critical path on a draft. Inspect whether holes, connector keepouts or rows of passives block the available channels. Set track widths, clearances and permitted via types, diameters, drills and layers against the project stackup and fabrication rules. Include via-in-pad or mask treatment when the layout or assembly needs it. If the escape needs a part move or outline change, take that change back to arrangement.
2. **Route critical connections deliberately.** Use KiCad's interactive router or a targeted tool for differential pairs, supply and return loops, and other nets with specific geometry. Reserve space for their reference paths. Check that the bulk pass preserves the existing copper and geometry constraints on a small working copy. A tool that also moves parts or edits the schematic needs an explicitly scoped placement or schematic iteration. [KiCad PCB Editor](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html), [KiCad Routing Tools](https://github.com/drandyhaas/KiCadRoutingTools#command-line-interface)
3. **Route the ordinary remainder in a bounded pass.** Freerouting supports the KiCad Specctra DSN export and SES import workflow. Use the matching board copy for import. KiCad Routing Tools is an optional headless candidate for explicit net sets, differential pairs, fanout and planes. Start with a named subset and a separate output board, particularly when a whole-board command can adjust placement. Pin the tool version and settings for any route you keep. [KiCad DSN/SES exchange](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#_importing_specctra_session_files), [Freerouting CLI](https://github.com/freerouting/freerouting#command-line-interface-cli), [KiCad Routing Tools net selection](https://github.com/drandyhaas/KiCadRoutingTools#net-pattern-syntax)
4. **Diagnose the leftovers.** Refill planes, then compare KiCad's rule violations and unconnected items separately. For router or fanout trials, keep the starting placement and rules fixed and use separate output paths per attempt. Score only a fresh board from a completed run with its own fresh KiCad report. Record a crash or timeout as a failed attempt and retain its log. Inspect the locations, escaped pins and blocking tracks around open connections. Try a targeted change to route order, fanout or placement, or finish a few local connections interactively. Return to arrangement when the same blockage persists and a clean escape needs a placement change.

Track the routed board, annotated layer views, KiCad report and tool/rules versions. Before accepting a route, check that the intended nets are connected after zone fill, that the board still matches the schematic and accepted placement, and that critical nets meet their routing constraints. Document any deliberate exceptions. A report can show zero rule violations alongside a nonempty unconnected-items list.
